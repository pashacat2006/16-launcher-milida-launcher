# Millida + 16 — личная сборка

Цель: настоящее окно Millida с её каталогом, учётной записью и модом; установка обычного Minecraft, Java и запуск — кодом 16 Launcher внутри того же приложения.

## Как это устроено

- Библиотека сборок остаётся в `%APPDATA%\net.millida.launcher\profiles.json`. Существующие сборки появляются без экспорта. Новые сборки, скачанные в этом окне, попадают в ту же библиотеку.
- Миры, моды, настройки и скриншоты используются из исходной папки каждой сборки Millida. Второй копии сборки в отдельном 16 Launcher не создаётся.
- Движок 16 хранит служебные настройки и игровые файлы в `%APPDATA%\net.millida.launcher\engine16`. Отдельно установленный 16 Launcher для работы гибрида не требуется.
- Уже скачанные общие ресурсы и библиотеки Minecraft копируются из кеша Millida по мере необходимости; движок 16 проверяет их штатным способом. Моды и миры при этом не дублируются.
- Обычные загрузчики: vanilla, Fabric, Quilt, Forge и NeoForge. Сборки собственного формата Millida, нативные игры и Horizon используют исходный совместимый путь Millida.
- Двоичные загрузки каталога идут через HTTP-клиент 16, с сохранением проверки хешей, паузы и распаковки Millida. Каталог, авторизация и получение косметики по-прежнему обращаются к Millida: у 16 нет замены этим сервисам.
- Штатный мод Millida устанавливается её исходным кодом, для совместимой версии игры и загрузчика. Его отдельный сеансовый токен передаётся процессу игры в окружении. Аккаунт Millida не экспортируется в файлы аккаунтов 16.
- Доступен один процесс игры через движок 16 одновременно. Ускорение конкретной сборки нужно измерять: время загрузки самих модов и подключения к серверам от замены лаунчера не исчезает.
- Для обычного Minecraft недостающая музыка (`minecraft/sounds/music/*.ogg`) докачивается после запуска игры. Текстуры, языки, звуковые эффекты и прочие ресурсы готовятся до запуска. Большие ресурсы загружаются частями с проверкой полного SHA1; законченные части сохраняются при отмене и используются при продолжении. До окончания фоновой загрузки некоторые музыкальные композиции могут не играть.

## Запуск

После успешной сборки: `Start.cmd` или `Launcher\Millida16.exe`. Перед этим полностью выйди из оригинальной Millida через её значок в трее: обе копии используют одну библиотеку и защиту от повторного запуска. Не обновляй одну сборку одновременно в двух копиях.

Это отдельная личная копия. Её автообновление и автоматическая переустановка официальным установщиком отключены. Оригинальные установленные приложения не заменяются.

## Сборка и проверки

`pwsh -File .\Build.ps1` собирает интерфейс, проверяет его синтаксис и размер и создаёт EXE. `-CheckOnly` дополнительно проверяет Rust без создания EXE. Подготовленный локальный Rust находится в `.tools\toolchain`; Node.js и Visual Studio C++ должны быть установлены.

Исходники интерфейса и адаптера: `hybrid`. Исходники движка 16 и изменения для встраивания: `vendor\rust-launcher-main`. Логи текущей проверки — `.tools\frontend-build.log` и `.tools\backend-check.log`.

Исправление сети от 18.11.2026: неудачные предварительные HEAD-запросы больше не запрещают настоящую загрузку или использование готовых файлов. Описание уже скачанной версии Minecraft и профиль выбранного Fabric/Quilt берутся из кеша; клиентский JAR и индекс ресурсов также подхватываются из Millida. Проверены два сценария регрессии, сохранность существующей сборки и настоящий запрос к адресу Mojang из сообщения об ошибке (успешно, 1,29 с). Это проверка загрузочного кода; запуск Minecraft до меню пользователь проверяет отдельно.

Для задержки на 45% найдены 20 недостающих музыкальных ресурсов общим объёмом 274,7 МиБ. Проверены SHA1 всех 3830 обязательных ресурсов: отсутствующих и повреждённых нет. Ожидание музыки перед запуском убрано; фоновая докачка начинается после появления процесса игры. Проверки отмены, продолжения и целостности проходят вместе с остальными тестами runtime: 20 успешно. Логи: `.tools\background-tests.log`, `.tools\background-release-build.log`, `.tools\background-runtime-stderr.log`. Время выхода самой игры в меню ещё не измерено.

## Локальный профиль

На экране входа и в меню добавления аккаунтов доступен «Локальный профиль»: укажи ник из 3–16 латинских букв, цифр или `_`, затем выбери скин в гардеробе. Регистрация, почта и аккаунт Millida не нужны. Можно выбрать скин из каталога или импортировать свой PNG; настройки сохраняются на этом компьютере отдельно для каждого локального профиля в `local-profiles/<id>` внутри папки данных лаунчера.

При запуске через движок 16 используется офлайн-идентичность выбранного ника. Сессия Millida и токен входа для мода этому профилю не выдаются, даже если в лаунчере сохранён аккаунт Millida с таким же ником. В совместимых модовых сборках скин передаётся встроенному моду либо CustomSkinLoader. В чистой vanilla локальный скин не отображается; другим игрокам он автоматически не передаётся. Realms и серверы с проверкой лицензии требуют Microsoft, а серверы с входом Millida — отдельный профиль Millida. Платные вещи и облачный гардероб Millida остаются за аккаунтом Millida.

## Найти сервер

Плитка «Играть с друзьями» открывает две вкладки: «Свой сервер» и «Найти сервер». Во второй работает встроенный каталог Millida: категории, поиск, фильтры версии и типа входа, сортировка по онлайну. Для локального профиля по умолчанию выбраны серверы с входом по нику. В живой подборке скрыты записи, которые каталог отмечает как неработающие; доступность и онлайн берутся из API, а не задаются вручную.

Над «Играть» указаны версии сервера. Нажатие подбирает установленную обычную серверную сборку либо автоматически создаёт «Minecraft <версия>»; отдельная сборка с личными модами не изменяется. Подготовка игрового клиента, Java и запуск выполняются движком 16, с использованием существующих кешей. Адрес сервера передаётся в запуск для автоматического подключения. Точная версия патча, например 1.21.1, больше не считается совместимой с любым другим патчем 1.21; если каталог сообщает только семейство версии, лаунчер уточняет его пингом. Необязательный каталог FPS-модов не задерживает создание серверной сборки.

Проверки выбора версии, создания и повторного использования сборки, передачи адреса и отказа до установки при неподходящем типе входа — `hybrid/src/lib/serverQuickJoin.test.ts`. Настоящий вход в Minecraft проверяется отдельно: правила регистрации, пароль и допуск на конкретный сервер задаёт его владелец.

На карточке и в подробностях сервера есть отметка доступности по странам. Если сведения отсутствуют, отображается белый значок с вопросом и «Нет данных по странам». Галочка «Разрешены все страны» требует явного подтверждения в данных; отсутствие сведений им не считается. Для известных ограничений показан чёрный флаг с крестом и отдельные списки стран: возможная недоступность и высокая задержка. Каталог сейчас не передаёт таких списков: лаунчер готов читать поле `regionalAvailability` с `blockedCountries`, `highLatencyCountries` (двухбуквенные коды стран), `allCountriesAllowed`, необязательными `sourceUrl` и `checkedAt`.

Для видимых карточек измеряется время ответа Minecraft status с текущего подключения, не более трёх запросов одновременно; результат сохраняется на две минуты и используется также в подробностях сервера. При ответе от 500 мс появляется «У тебя может сильно лагать». Это время ответа status, а не измерение TPS или доказательство блокировки страны. Неответивший сервер помечается как неответивший с текущего подключения; страна пользователя автоматически не определяется.

## GitHub проекта, баги и отзывы

Наш репозиторий: [pashacat2006/16-launcher-milida-launcher](https://github.com/pashacat2006/16-launcher-milida-launcher). Основная кнопка «Звезда на GitHub» ведёт сюда. Вторая кнопка подписана «Millida Launcher» и ведёт к исходному проекту. Награды за звёзды не начисляются. Ссылка на исходный код в настройках также ведёт в наш репозиторий; личная сборка не выдаётся за опубликованный выпуск Millida.

«Нашёл баг» и «Написать отзыв» готовят сообщение в [Issues нашего проекта](https://github.com/pashacat2006/16-launcher-milida-launcher/issues). Нужен аккаунт GitHub; пользователь проверяет текст и нажимает `Submit new issue` на GitHub. Сообщение публичное. В него включаются введённый текст, выбранная категория или оценка и версия лаунчера; логи и токены автоматически не добавляются. Очень длинный текст переносится через буфер обмена, чтобы избежать ошибки слишком длинного URL. Отправка новых отзывов и багов в Millida, проверка прежней награды за отзыв и уведомления о её баг-репортах в этом форке отключены.

Для этой схемы GitHub Packages не требуется:

| Сервис | Для чего нужен здесь |
| --- | --- |
| GitHub Issues | Баги и отзывы, с дальнейшими ответами в комментариях |
| GitHub Releases | Раздача готового EXE и описания обновлений |
| GitHub Packages | Реестр зависимостей, например npm-пакетов и контейнеров; не почтовый ящик для отзывов |

Публичные Packages бесплатны. Для приватных пакетов GitHub Free включает 500 МБ хранилища и 1 ГБ передачи данных в месяц; хранилище учитывается совместно с артефактами Actions. Это отдельные лимиты, которые не нужны для открытия Issues. Источники: [назначение Packages](https://docs.github.com/en/packages/learn-github-packages/introduction-to-github-packages), [тарифы Packages](https://docs.github.com/en/billing/managing-billing-for-your-products/managing-billing-for-github-packages/about-billing-for-github-packages).
